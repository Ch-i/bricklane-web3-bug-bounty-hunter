# [I-01] ERC4626 compliance issues

_Section severity (from Solodit section header): Informational_  
_Audit firm: CODESPECT_  
_Source report: [2025-10-21-lstOlas.md](https://github.com/solodit/solodit_content/blob/main/reports/CODESPECT/2025-10-21-lstOlas.md)_

---

**Files:** [`stOLAS.sol`](https://github.com/LemonTreeTechnologies/olas-lst/tree/e9d19b7fb08288f829cba8243d91e80ebde745a6/contracts/l1/stOLAS.sol)

**Description:**

The stOLAS contract is supposed to be fully compliant with the ERC4626 vault standard for maximum DeFi composability. However, there is an instance where this is not true. The `maxMint(...)` and `maxWithdraw(...)` functions should always return 0, because mints and withdrawals are disabled.

**Status:** Fixed

**Client response:** Maybe revert?

- [`ERC4626.sol#L164`](https://github.com/transmissions11/solmate/blob/main/src/tokens/ERC4626.sol#L164)
- [`ERC4626.sol#L168`](https://github.com/transmissions11/solmate/blob/main/src/tokens/ERC4626.sol#L168)

**CODESPECT fix review:** According to the EIP, these functions "MUST NOT" revert. For full compilance they should return 0. Source: [EIP-4626](https://eips.ethereum.org/EIPS/eip-4626)

**Client response:** PR with fix: [https://github.com/kupermind/olas-lst/pull/42](https://github.com/kupermind/olas-lst/pull/42)
