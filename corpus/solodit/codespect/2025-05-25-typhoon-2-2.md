# [M-03] notesCount is not updated during the execution of updateNotes(...)

_Section severity (from Solodit section header): Medium_  
_Audit firm: CODESPECT_  
_Source report: [2025-05-25-Typhoon.md](https://github.com/solodit/solodit_content/blob/main/reports/CODESPECT/2025-05-25-Typhoon.md)_

---

**Files:** [`NoteAccount.cairo`](https://github.com/typhoonmixer/typhoon-contracts/blob/a148cf0c83d28e98b1bd21af301bfd55f9a9c3f7/src/NoteAccount.cairo#L101-L107)

**Description:**

The `notesCount` storage mapping tracks the number of notes associated with each public key. However, this value is not updated during the execution of `updateNotes(...)`. As a result, after a note update, the stored count may no longer reflect the actual number of notes. The internal `eraseNotes(...)` function should reset the note count to zero, and during the loop in `updateNotes(...)`, the count should be incremented on each iteration.

```cairo
loop {
    self.notes.entry(pubKey).entry(i.into()).write((
        *newNotes[i][0], *newNotes[i][1], *newNotes[i][2],
        *newNotes[i][3], *newNotes[i][4], *newNotes[i][5],
        *newNotes[i][6]
    ));
    i += 1;
    if (newNotes.len() == i) {
        break;
    }
    // @audit update the note count
}
```

**Impact:** Incorrect tracking of note counts can lead to inconsistencies and unexpected behavior in contract logic that depends on the accurate number of notes per public key.

**Recommendation:** Ensure `eraseNotes(...)` resets the count to zero, and increment `notesCount` in each iteration of the update loop to maintain consistency.
