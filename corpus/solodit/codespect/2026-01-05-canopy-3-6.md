# [I-07] Lacking an on-chain authorization check allows growth_cycle creation by anyone

_Section severity (from Solodit section header): Informational_  
_Audit firm: CODESPECT_  
_Source report: [2026-01-05-Canopy.md](https://github.com/solodit/solodit_content/blob/main/reports/CODESPECT/2026-01-05-Canopy.md)_

---

**Files:** [`create.rs`](https://github.com/canopyfi/canopy/blob/234cd9ca0ca8348e466548513d72a2aba65e84e4/programs/canopy/src/instructions/growth_cycle/create.rs#L54)

**Description:**

For the creation of `growth_cycle` the comments mention that authorization is off-chain and only Platform admins and Seedling admins are allowed to call the `create(...)` instruction.

```rust
pub fn handler(...) -> Result<()> {
    //...
    // NOTE: Admin authorization check is handled at the application layer.
    // Only Platform admins and Seedling admins should be allowed to call this instruction.
    // The authority signer ensures proper authentication, and additional role checks
    // can be enforced in the frontend/backend before submitting transactions.
}
```

However, the lack of on-chain authorization allows anyone to directly send a transaction to create a `growth_cycle` account.

**Impact:** An unauthorized `growth_cycle` account may be created under a Seedling.

**Recommendation:** It is recommended to add on-chain authorization checks to the `create(...)` instruction.

**Status:** Fixed
