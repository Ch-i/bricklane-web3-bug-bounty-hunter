# [I-16] Unnecessary 64-byte validation for operation_data in time_lock::execute(...) instruction for OperationType::UpdateInvestmentDestination

_Section severity (from Solodit section header): Informational_  
_Audit firm: CODESPECT_  
_Source report: [2026-01-05-Canopy.md](https://github.com/solodit/solodit_content/blob/main/reports/CODESPECT/2026-01-05-Canopy.md)_

---

**Files:** [`execute.rs`](https://github.com/canopyfi/canopy/blob/234cd9ca0ca8348e466548513d72a2aba65e84e4/programs/canopy/src/instructions/time_lock/execute.rs#L164)

**Description:**

In the `UpdateInvestmentDestination` operation, the instruction enforces that `operation_data` must be exactly 64 bytes long. However, this requirement is unnecessary because the instruction does not actually use the first 32-bytes of the `operation_data` to derive or decode the previous destination address. Instead, the old destination is obtained directly from `plot.investment_destination_wallet`, making the strict length check redundant and unnecessary.

```rust
require!(operation_data.len() == 64, ErrorCode::InvalidInput);

//...
//...

let old_destination = plot.investment_destination_wallet;
```

**Impact:** he incorrect 64-byte requirement results in an unnecessary waste of 32 bytes of input data, providing no functional or security benefit. This adds minor overhead and contributes to inefficient instruction design without affecting system behavior.

**Recommendation:** Remove or relax the 64-byte requirement for `operation_data` when handling `UpdateInvestmentDestination`, as it is not needed for the operation’s logic.

**Status:** Fixed

**Client response:** <https://github.com/canopyfi/canopy/commit/d9db31ab94ce21509ce89fdca30b6dd2f347549f>

**CODESPECT fix review:** In `propose`, `OperationType::UpdateInvestmentDestination` does not allow `new_destination` to be default. But in `execute`, when `new_destination` is default, it is treated as `None`. This is an inconsistency.
