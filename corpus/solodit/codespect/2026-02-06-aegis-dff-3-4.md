# [I-05] seedPoolFromPosition(...) function doesn’t check liquidity position’s type

_Section severity (from Solodit section header): Informational_  
_Audit firm: CODESPECT_  
_Source report: [2026-02-06-Aegis-DFF.md](https://github.com/solodit/solodit_content/blob/main/reports/CODESPECT/2026-02-06-Aegis-DFF.md)_

---

**Files:** [`AegisDFF.sol`](https://github.com/labs-solo/AEGIS_DFF/blob/main/contracts/AegisDFF.sol#L489)

**Description:**

The `seedPoolFromPosition(...)` function accepts an existing Uniswap V4 NFT liquidity position and stores it in the vault’s `limitId` slot without verifying whether the position is one-sided or balanced. While there is no technical impact, `limitId` positions are expected to be one-sided AG-token positions from the `seedPool()` function. This creates potential confusion about position classification without causing functional issues.

**Impact:** Position classification inconsistency.

**Recommendation:** Consider checking the position’s type in `seedPoolFromPosition(...)`.

**Status:** Acknowledged

**Client response:** This could be the case but would be fixed upon rebalances. This is done to have additional confidence for the first three weeks when we might have external liquidity providers involved and it would be more comfortable for them to see safety mechanisms they understand such as standard timelock / safe rather than AG token in AegisDFF.

**CODESPECT fix review:** We are going to marked as acknowledged.
