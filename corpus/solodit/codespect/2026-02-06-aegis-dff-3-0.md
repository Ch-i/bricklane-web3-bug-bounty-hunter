# [I-01] Last AG token fee paid by the user will be stuck in the contract

_Section severity (from Solodit section header): Informational_  
_Audit firm: CODESPECT_  
_Source report: [2026-02-06-Aegis-DFF.md](https://github.com/solodit/solodit_content/blob/main/reports/CODESPECT/2026-02-06-Aegis-DFF.md)_

---

**Files:** [`AegisDFF.sol`](https://github.com/labs-solo/AEGIS_DFF/blob/e8d5ed8a07a09a6d36d0c1401e66957540d90093/contracts/AegisDFF.sol#L390)

**Description:**

The `emergencyWithdraw(...)` function in the AegisDFF contract is designed to rescue ERC20 tokens that are stuck in the contract. However, it explicitly blocks the withdrawal of the AG token. This creates a scenario where AG tokens that accumulate in the vault through redemption fees cannot be recovered via `emergencyWithdraw(...)`. This can happen if the last remaining shareholder redeems their position via `redeemFromPositions(...)` or `redeemToOther(...)`, which will leave the fees in the contract.

**Impact:** AG tokens accumulated from the last redemption fee will be stuck in the contract.

**Recommendation:** Consider removing the token restrictions from `emergencyWithdraw(...)` function when there is no share supply.

**Status:** Fixed

**Client response:** Fair point, I never see this arising realistically since there will always be a depositor who will forget, however even if we do run into this circumstance we can should be able to keep this to dust amounts of the AG token.
