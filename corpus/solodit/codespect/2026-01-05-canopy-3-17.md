# [I-18] Missing validation for default and duplicate values in platform::update_fees_wallet and grove::create

_Section severity (from Solodit section header): Informational_  
_Audit firm: CODESPECT_  
_Source report: [2026-01-05-Canopy.md](https://github.com/solodit/solodit_content/blob/main/reports/CODESPECT/2026-01-05-Canopy.md)_

---

**Files:** [`update_fees_wallet.rs`](https://github.com/canopyfi/canopy/blob/d17092d2a2aab52b0f79634f90bd8890391111e5/programs/canopy/src/instructions/platform/update_fees_wallet.rs), [`create.rs`](https://github.com/canopyfi/canopy/blob/d17092d2a2aab52b0f79634f90bd8890391111e5/programs/canopy/src/instructions/grove/create.rs)

**Original severity:** Best Practices

**Description:**

In the `platform::update_fees_wallet` instruction, there is no validation to ensure that the `new_fee_wallet` is different from the previously configured fee wallet or that it is not set to the default `Pubkey`. This allows redundant or invalid updates that do not meaningfully change platform configuration. Similarly, in the `grove::create` instruction, several critical fields such as `name`, `fee_wallet`, `onboarding_fee`, and `platform_fees` are not validated against default or empty values. The absence of these checks permits the creation of grove accounts with null or unintended configurations.

**Impact:** These missing validations do not introduce a direct security vulnerability but can lead to misconfigured platform and grove states.

**Recommendation:** Add explicit validation to ensure that `new_fee_wallet` is neither the default public key nor identical to the existing fee wallet before applying updates. Additionally, enforce checks in `grove::create` to prevent default or empty values for critical fields, ensuring all newly created groves start in a valid and intentional configuration state.

**Status:** Fixed
