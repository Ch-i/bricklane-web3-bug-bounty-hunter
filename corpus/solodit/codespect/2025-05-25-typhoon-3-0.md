# [I-01] Adding a pool with the same token and denomination of another pool will override it in the pools mapping

_Section severity (from Solodit section header): Informational_  
_Audit firm: CODESPECT_  
_Source report: [2025-05-25-Typhoon.md](https://github.com/solodit/solodit_content/blob/main/reports/CODESPECT/2025-05-25-Typhoon.md)_

---

**Files:** [`Typhoon.cairo`](https://github.com/typhoonmixer/typhoon-contracts/blob/a148cf0c83d28e98b1bd21af301bfd55f9a9c3f7/src/Typhoon.cairo#L183)

**Description:**

The `pools` mapping keeps track of all the pools deployed according to their token and denomination only. If a new pool gets deployed with the same token and denomination of another pool, the new pool address will override the old one’s at the mapping, which is only used in the `getPool(...)` function.

```cairo
fn addPool(
    ref self: ContractState, _token: ContractAddress, _denomination: u256, _day: u256,
) {
    ...
    self.pools.entry(_token).entry(_denomination).write(pool_address);
    self.pool_salt.write(self.pool_salt.read() + 1);
    self.allowed_pools.entry(pool_address).write(true);
}
```
