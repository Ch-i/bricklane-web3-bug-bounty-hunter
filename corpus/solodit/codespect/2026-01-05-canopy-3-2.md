# [I-03] Inconsistent plot parameter validation

_Section severity (from Solodit section header): Informational_  
_Audit firm: CODESPECT_  
_Source report: [2026-01-05-Canopy.md](https://github.com/solodit/solodit_content/blob/main/reports/CODESPECT/2026-01-05-Canopy.md)_

---

**Files:** [`accept.rs`](https://github.com/canopyfi/canopy/blob/1b3b043dc962bbab89ffbcb1052650f4eea58dbc/programs/canopy/src/instructions/plot/accept.rs), [`approve.rs`](https://github.com/canopyfi/canopy/blob/1b3b043dc962bbab89ffbcb1052650f4eea58dbc/programs/canopy/src/instructions/plot/approve.rs), [`update.rs`](https://github.com/canopyfi/canopy/blob/1b3b043dc962bbab89ffbcb1052650f4eea58dbc/programs/canopy/src/instructions/plot/update.rs)

**Description:**

There is inconsistent range validation for relevant parameters throughout the plot lifecycle.

a. The `accept(...)` instruction does not call `validate_fee_structure` when modifying `grove_fees`;

b. The `approve(...)` instruction does not call `validate_amounts` when modifying `new_allocation` and `new_minimum_investment`, thus missing the `max_safe_allocation` check;

c. The `update(...)` instruction lacks `validate_dates`, `validate_fee_structure`, and `validate_amounts` checks when modifying parameters;

**Impact:** The range checks for plot parameters during updates differ from those at plot creation, allowing parameters to be set out of bounds during updates.

**Recommendation:** It is recommended to enforce the same checks during parameter updates as those applied at plot creation.
