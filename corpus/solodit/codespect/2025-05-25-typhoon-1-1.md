# [H-02] withdraw_fee remains stuck in contract with no withdrawal mechanism

_Section severity (from Solodit section header): High_  
_Audit firm: CODESPECT_  
_Source report: [2025-05-25-Typhoon.md](https://github.com/solodit/solodit_content/blob/main/reports/CODESPECT/2025-05-25-Typhoon.md)_

---

**Files:** [`Pool.cairo`](https://github.com/typhoonmixer/typhoon-contracts/blob/a148cf0c83d28e98b1bd21af301bfd55f9a9c3f7/src/Pool.cairo#L231)

**Description:**

The `withdraw_fee` is deducted from each withdrawal and represents 0.5% of the denomination amount:

```cairo
IERC20Dispatcher { contract_address: self.token.read() }
.transfer(
    recipient, // @audit-issue withdraw_fee is not sent anywhere
    ((self.denomination.read() - self.withdraw_fee.read()) - *value[5])
    + reward,
);
```

While the fee is correctly subtracted, it is not transferred to any address and remains stuck within the contract. The fee is intended to reward liquidity providers. Although the reward mechanism may be removed before launch, the fee mechanism itself is meant to stay. However, there is currently no function available to withdraw or utilize the accumulated fees.

**Impact:** Fees accumulate in the contract with no way to access or distribute them. Since the contract is not upgradeable, this results in a permanent loss of funds.

**Recommendation:** Implement functionality to withdraw the accumulated fees or automatically transfer the fee to a designated address during each withdrawal.

**Status:** Fixed

**Client response:** Solved [1fa6a6d6462c66d8ce271b077a0420a7bcbfafdf](https://github.com/typhoonmixer/typhoon-contracts/commit/1fa6a6d6462c66d8ce271b077a0420a7bcbfafdf)

**CODESPECT fix review:** The issue was addressed by introducing a new function for withdrawing profits. However, a new function for updating the fee was also added. The problem with this `setWithdrawFee` function is that it does not enforce any upper bound on the fee value, which may lead to potential misuse or misconfiguration.
