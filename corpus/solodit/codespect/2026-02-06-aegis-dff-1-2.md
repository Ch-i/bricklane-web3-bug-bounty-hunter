# [M-03] Redeeming 0 assets doesn’t transfer the recently deleted tokens

_Section severity (from Solodit section header): Medium_  
_Audit firm: CODESPECT_  
_Source report: [2026-02-06-Aegis-DFF.md](https://github.com/solodit/solodit_content/blob/main/reports/CODESPECT/2026-02-06-Aegis-DFF.md)_

---

**Files:** [`AegisDFF.sol`](https://github.com/labs-solo/AEGIS_DFF/blob/main/contracts/AegisDFF.sol#L909)

**Description:**

The `redeem(...)` and `withdraw(...)` functions that call the `_redeemToAg(...)` function don’t transfer the recently deleted tokens to the user if the withdrawn assets are 0:

```solidity
function _redeemToAg(uint256 shares, address receiver, address owner) internal returns (uint256 assets) {
    // ...
    if (assets == 0) {
        return 0;
    }

    agToken.transfer(receiver, assets);

    // Transfer recently deleted tokens proportionally (no fee for redeem to AG)
    _transferRecentlyDeletedTokens(receiver, shares, supply, netBps);

    emit Redeemed(owner, receiver, shares, Currency.wrap(asset()), assets);

    return assets;
}
```

For example, if all the pools get removed and users should only receive the recently deleted tokens for their redemptions, calling these functions will burn their shares and they will receive nothing. This is handled properly on the other redeem functions.

**Impact:** Users don’t receive their portion of the recently deleted tokens if their withdrawn assets are 0.

**Recommendation:** Consider moving the `_transferRecentlyDeletedTokens(...)` call before the `assets == 0` check.

**Status:** Fixed
