# [I-02] Missing deadline parameter in AegisWithdrawal redemption functions to execute at outdated vesting rates

_Section severity (from Solodit section header): Informational_  
_Audit firm: CODESPECT_  
_Source report: [2026-02-06-Aegis-DFF.md](https://github.com/solodit/solodit_content/blob/main/reports/CODESPECT/2026-02-06-Aegis-DFF.md)_

---

**Files:** [`AegisWithdrawal.sol`](https://github.com/labs-solo/AEGIS_DFF/blob/e8d5ed8a07a09a6d36d0c1401e66957540d90093/contracts/AegisWithdrawal.sol#L46)

**Description:**

The AegisWithdrawal contract provides helper functions (`redeemToAg(...)`, `redeemToOther(...)`, `redeemFromPositions(...)`) that burn vested AegisShares and redeem the resulting DFF tokens via the vault. These functions accept a `minAmountOut` for slippage protection but do not accept a deadline parameter.

```solidity
function redeemToAg(
    uint256 shareAmount,
    uint256 minAmountOut
) external nonReentrant returns (uint256 agOut, uint256 dffClaimed) {
    dffClaimed = _claimVestedDff(msg.sender, shareAmount);
    // @audit No deadline - transaction can execute far in the future
    agOut = aegisDff.redeem(
        dffClaimed, msg.sender, address(this), minAmountOut
    );
}
```

The `AegisShares.claimAegisDff(...)` calculates the DFF amount based on the current `redeemablePercent()`, which increases linearly with time. If a transaction is stuck in the mempool, it will execute at a higher vesting percentage than the user intended. The `minAmountOut` was set based on the original vesting rate, so it no longer accurately reflects slippage protection.

**Impact:** A user submitting a redemption transaction may receive a different amount of DFF than expected if the transaction is delayed. Because `redeemablePercent()` increases over time, a delayed transaction claims more DFF from the AegisShares contract, which could disadvantage other shareholders who expected the original vesting schedule.

**Recommendation:** Add a `deadline` parameter to all three redemption functions and revert if `block.timestamp > deadline`.

**Status:** Fixed

**Client response:** These are the difference of seconds even minutes, and minAmountOut is going to have a .3% difference under intended output. This function works properly and deadline is really not necessary.

**CODESPECT fix review:** Will decrease the severity and leave as acknowledged

**Client response:** Added deadline: [5b86647769ae04e8d5e2a7e4e769067b164c22ed](https://github.com/labs-solo/AEGIS_DFF/commit/5b86647769ae04e8d5e2a7e4e769067b164c22ed)
