# [L-02] The AegisDFF vault is not fully EIP-4626 compliant

_Section severity (from Solodit section header): Low_  
_Audit firm: CODESPECT_  
_Source report: [2026-02-06-Aegis-DFF.md](https://github.com/solodit/solodit_content/blob/main/reports/CODESPECT/2026-02-06-Aegis-DFF.md)_

---

**Files:** [`AegisDFF.sol`](https://github.com/labs-solo/AEGIS_DFF/blob/main/contracts/AegisDFF.sol)

**Description:**

The AegisDFF vault has the following features which are not EIP-4626 compliant:

1. The `maxMint(...)` and `maxDeposit(...)` functions must not revert.
2. The `withdraw(...)` function must revert if all of assets cannot be withdrawn (due to withdrawal limit being reached, slippage, the owner not having enough shares, etc).
3. The `withdraw(...)` function should round up to calculate the shares required from the assets.
4. The `redeem(...)` and `withdraw(...)` functions must emit an event named `Withdraw` with the inputs of `(sender, receiver, owner, assets, shares)`.

**Impact:** Other contracts interacting with the AegisDFF vault will expect different behavior than the actual one.

**Recommendation:** Consider implementing the following changes:

1. The functions should return 0 instead of reverting.
2. The `withdraw(...)` function should revert if user’s shares can’t match the requested assets amount.
3. The `mulDivUp` function should be used to calculate the shares from the assets.
4. The withdrawing functions should implement the event mentioned in the report.

**Status:** Acknowledged

**Client response:** We are aware, we did everything in our power to keep it as compliant. Events were removed for contract size requirements but will be readded if possible. If not the AegisWithdraw will have events to show redemptions.

**CODESPECT fix review:** Leaving as Acknowledged

**Client response:** Fixed all except 2: [320eae4292cba1bd40d8f33501e667d4c83363c0](https://github.com/labs-solo/AEGIS_DFF/commit/320eae4292cba1bd40d8f33501e667d4c83363c0) We don’t want to potentially hinder user experience from withdrawals failing. We are not planning to use the standard redeem and withdraw function in our UI but rather our custom functions in AegisWithdrawal that will allow us to more accurately portray withdrawals via static calls and ensure safe withdrawals from slippage protection.
